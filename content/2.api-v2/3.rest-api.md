## Auth

You should already have an API key. If not please check out the [Getting Started](/introduction/getting-started) page.

Your API key should be present in the `Authorization` header on every request to the API.
Prefix your API key with the word `Bearer`.

> Assuming your API key is "ABCDEFGHIJKLMNOPQRSTUVWXYZ", this is how your header should look like:\
> `Authorization: Bearer ABCDEFGHIJKLMNOPQRSTUVWXYZ`


## Compatibility Date

Please read up on [Compatibility Dates](/api-v2/concepts#compatibility-dates) first.

The REST API lets you set the compatibility date on every request. You can provide it in one of two ways:

- As the `compatibility_date` query parameter, e.g. `?compatibility_date=2026-11-15`
- As the `X-Compatibility-Date` header, e.g. `X-Compatibility-Date: 2026-11-15`

If both are present, the query parameter is used.

If you provide neither, the latest version is used. This means the data format can change at any moment without notice, so you should always set a compatibility date.

Every response includes an `X-Compatibility-Date` header containing the compatibility date the data was delivered in.

A compatibility date in an invalid format will return a `400` with a `fsb:problem:api:invalid_compatibility_date` problem.

If you are on the free tier you only have access to endpoints in the "static" group.
Upgrade to get access to content endpoints.
